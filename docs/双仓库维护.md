# 两个仓库的分工

| 仓库 | 用途 | 接收条件 |
| --- | --- | --- |
| [Lightn233/padavan](https://github.com/Lightn233/padavan) | 已有稳定界面、日常版本及回退基线 | 底层修复完成对应实机回归后合入主分支 |
| [Lightn233/padavan-modern](https://github.com/Lightn233/padavan-modern) | 新版界面开发 | 当前是预览源码，浏览器和整机验收未完成，不发布为稳定固件 |

新仓库保留共同 Git 历史。由于同一账号已有该项目的 fork，新仓库采用独立仓库形式，不伪装成第二个 GitHub 原生 fork。原作者、许可、工具链、机型配置和 `make RM2100` 入口继续保留。

维护原则：

1. 网络、内核、驱动、工具链、公共脚本修复单独提交，记录测试范围，两个仓库使用同一提交或明确记录 cherry-pick 来源。
2. 界面专属变化留在现代界面仓库；共享后端协议变更应兼容旧界面，不能要求稳定版同时更换界面。
3. 尚未完成实机验证的底层修复只进候选分支。本轮 `wan6_solicit_ppp` 已过隔离 RS/RA 模拟与 MIPS 编译，但自动拨号路径仍待实机验证。
4. 只推送明确的分支和提交，不用 `push --mirror` 覆盖另一仓库。同步前先核对远端是否有他人修改。
5. 不上传用户 NVRAM、AGH 配置、密码、抓包、虚拟磁盘、构建目录或 `node_modules`。测试使用固定模拟输入。

同步公共修复时，在已有检出中增加另一个 remote，再检查和挑选提交即可，不需要另复制完整源码目录：

```sh
git remote add stable https://github.com/Lightn233/padavan.git
git fetch stable main
git log --oneline HEAD..stable/main
# 核对具体修复后执行 git cherry-pick <提交号>，运行对应回归。
```

这份维护约定不意味着无人值守的永久后台同步。每次修改都要留下可核对的提交、测试结果和剩余验收项。
