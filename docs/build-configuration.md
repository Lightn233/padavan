# 编译前配置：给第一次编译的用户

不知道某项用途时，保留默认即可。公共源码默认不超频，RM2100 的板级资源参数按原厂 **128 MiB RAM** 设置；不是维护者改装机的 512 MiB。机型原始参数可对照[上游 RM2100 板级定义](https://github.com/tsl0922/padavan/blob/main/trunk/configs/boards/RM2100/board.mk)。

## 最简单的使用方法

在源码最外层目录运行：

```sh
make menuconfig
```

先选机型，再按中文说明修改需要的项目。也可以直接打开指定机型：

```sh
make menuconfig MODEL=RM2100
```

菜单中 `6` 查看汇总，`s` 保存退出，`q` 放弃本次修改。保存前会显示与公共默认相比改了什么，并要求输入 `yes`。按 Ctrl+C 或取消不会保存。

保存以后再编译：

```sh
make config-show MODEL=RM2100
make RM2100
```

`make menuconfig` 只配置，不自动编译、刷机或访问路由器。不要写成 `make menuconfig RM2100`，那是同时执行两个 make 目标。原有 `make RM2100`、`make K2P` 等方式继续可用；自动构建不会突然弹出交互菜单。

## 选项分别是什么意思

| 项目 | 用途 | 不清楚时怎么选 |
| --- | --- | --- |
| 机型 | 选择芯片、板级驱动、闪存布局和模板 | 必须与路由器实际型号一致 |
| CPU 频率 | 改变处理器时钟，可能提高 CPU 运算速度 | 不超频 |
| 物理内存规格 | 为连接数、缓存等编译期资源参数选择 RAM 容量 | 未改装选机型默认 |
| `/tmp` 容量 | 临时文件和部分日志能使用的 RAM 上限 | 自动 |
| `/etc` 容量 | 运行时配置文件所在 RAM 文件系统的上限 | 自动 |
| 插件 | 决定固件包含哪些程序/管理入口 | 只选自己需要的，不是越多越快 |
| 界面语言 | 增加网页界面的语言资源 | 保留默认中文；英语基础资源始终保留 |

### CPU：关闭超频是什么意思

关闭 `CONFIG_FIRMWARE_INCLUDE_OC` 后，固件不重写 CPU 调频寄存器，沿用引导程序设置。**如果你已在 Breed 等引导程序中超频，本开关不会替你恢复引导程序的频率。** 菜单不会操作 Breed、Bootloader 或 Factory。

MT7621 菜单沿用源码已有的这些档位，下面的标称频率对应 RM2100 的时钟条件；其他板型仍需核对晶振和启动日志：

| 菜单档位 | `CONFIG_FIRMWARE_MT7621_OC` |
| --- | --- |
| 1000 MHz | `0x312` |
| 1100 MHz | `0x362` |
| 1120 MHz | `0x372` |
| 1200 MHz | `0x3B2` |

这些档位是可选参数，不是每一台机器都稳定的承诺。CPU 体质、供电和散热不同；应有已验证的回退固件，刷入后核对 `CPU Clock` 日志，并验证负载下是否重启、报错或掉线。新用户建议保持关闭。

### 内存：不是扩容按钮

RAM 是程序运行时使用的内存；Flash 是保存固件和持久文件的存储，两者不同。256/512 MiB 选项适用于已经更换物理 RAM 芯片的设备，不会把原厂 128 MiB 变成 512 MiB。

菜单值通过 `CONFIG_FIRMWARE_RAM_SIZE` 覆盖用户程序的 `BOARD_RAM_SIZE`，影响缓存、连接数等资源参数。内核仍使用原有物理内存探测，不伪造设备树内存、不修改 DDR 时序，也不写引导程序。系统显示的可用内存扣除了保留区和内核等占用，不必等于标称容量。

### `/tmp`、`/etc`：只是 RAM 使用上限

这里的 MiB 是容量单位。设置上限不会立即占用全部 RAM，文件增长时才消耗内存；重启、断电后临时文件会消失。

默认沿用现有启动策略：普通模式 `/tmp` 24 MiB、`/etc` 6 MiB；启动时实际 `MemTotal` 达到 256 MiB 时为 64/16 MiB；低内存模式保留原限制。标称 256 MiB 的机器，扣除保留内存后不一定满足后一个条件。

`/etc/storage` 在运行时共用 `/etc`，其保存到 Flash 的机制保持原样。扩大 `/etc` **不会扩大 Flash 的 Storage 分区**。自定义值还会按实际可用内存复核；上限合计过大时继续使用自动值。

### 插件：勾选后还需要配置

每个插件进入选择项后会说明用途和公共默认。DDNS 需要域名及服务商账号，VPN/组网需要对端或控制器，IPTV 需要运营商线路，存储和下载服务需要实际存储设备。编译进固件不等于账号、线路或硬件已经准备好。

此菜单只展示当前模板或公共覆盖已经声明的常用插件入口，不声称覆盖所有底层内核选项。USB/存储及真实服务商环境的验收范围见 [测试状态](validation.md)。插件会增加固件体积；是否装得下以构建产物和刷写检查为准。

## 配置存在哪里，怎么手工修改

优先级是：**机型模板 → `hello/common.override` → `hello/local/<机型>.override`**。个人文件已被 Git 忽略，不会因为发布源码而把个人选择变成大家的默认值。K2P、K2P-NANO 等入口也分别保存，不串用。

例如，有实际 512 MiB RAM、并自行决定使用 1100 MHz 的 RM2100，可在 `hello/local/RM2100.override` 写：

```makefile
CONFIG_FIRMWARE_INCLUDE_OC=y
CONFIG_FIRMWARE_MT7621_OC=0x362
CONFIG_FIRMWARE_RAM_SIZE=512
```

需要明确指定临时目录上限时，再加：

```makefile
CONFIG_FIRMWARE_TMPFS_TMP_MIB=64
CONFIG_FIRMWARE_TMPFS_ETC_MIB=16
```

这里是硬件改装示例，不是推荐所有用户照抄。超频默认关闭的公共位置仍是 `hello/common.override`，RM2100 原厂 RAM 默认位置是 `trunk/configs/boards/RM2100/board.mk`；个人选择优先放在 `hello/local/`。

## 切换配置后要不要清理

改变机型、CPU、内存规格、插件或语言开关，并且目录中有旧编译产物时，入口会在覆盖旧构建配置之前停止并提示清理：

```sh
make clean
make RM2100
```

清理保留 `hello/local/RM2100.override`，不删除工具链和下载包。首次编译不需要先清理；只调整临时目录上限时直接在安装阶段重新生成对应文件。

菜单中选择“恢复公共默认”，再保存，即可取消该机型的个人覆盖。恢复默认也不自动刷机，仍需重新构建并自行按已验证流程更新设备。

## 检查菜单是否正常

在 Ubuntu 源码根目录运行 `python3 tests/build/test_build_config.py`。测试只复制少量配置到临时目录，检查保存/取消、机型隔离、默认值和构建配置生成，不需要完整工具链，不会刷机。菜单通过不等于各超频档位或所有插件组合已经通过实机稳定性测试。
